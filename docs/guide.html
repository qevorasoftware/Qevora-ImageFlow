ImageFlow user guide

ImageFlow creates local alternatives for Media Library uploads and can display those alternatives in WordPress and Elementor. Start with one image and one published page.

Setup · Bulk workflow · Page Inspector · Template comparison · Restore · Tools and troubleshooting

1. Configure and convert a sample

  1. Upload the installable ZIP under Plugins → Add New, activate it, then open Qevora ImageFlow → Settings.
  2. Select the original formats under Convert from. JPEG and PNG are enabled by default. GIF, WebP, AVIF, BMP, TIFF, HEIC and HEIF depend on available decoders. A disabled checkbox has an explanation underneath.
  3. Choose one or more outputs under Generate and one preferred delivery format. For example, select JPEG and PNG as inputs, generate WebP, and prefer WebP. Reading and writing a format require different codec capabilities.
  4. In Media Library, open an attachment and use Convert now. Compare the original and generated previews and byte counts. Existing attachment IDs and original files stay usable.

Conversion settings

  • Automatic upload conversion schedules work through WP-Cron. Bulk Converter processes older uploads.
  • WebP, AVIF and JPEG quality control the encoder. PNG compression controls lossless compression effort. Keep only smaller alternatives skips copies that do not reduce bytes.
  • Select the WordPress intermediate sizes used by your pages. Maximum MB and megapixels apply per input file. Enter comma-separated attachment IDs to exclude specific media.
  • Metadata stripping applies to generated files. Imagick can retain ICC data. GD has more limited metadata support. Animated or multi-frame images, orientation-sensitive images and transparency-losing conversions may be skipped.
  • Delivery, Elementor delivery and background optimization can be toggled separately as described under each control. Changing encoder settings requires another conversion for existing images.

2. Process existing images

  1. Open Bulk Converter. Choose checked rows, all eligible images, failed images, or force reconvert checked images.
  2. Use the original-format, status and upload-month filters to find rows. A library-wide batch scans all eligible sources independently of the visible filters.
  3. Choose output formats for this batch. Review the scope and click Start conversion. Keep the page open. Progress and result rows update through AJAX.
  4. Pause between attachments, resume from the saved position, or stop. Completed files remain usable. Use Last result to investigate a failed or skipped row.

The Dashboard reports pending, converted, skipped and failed attachments and compares source bytes with one alternative per size. This is a file-size comparison. Actual network traffic depends on browser selection and caching.

3. Inspect an Elementor or WordPress page

  1. Sign in as an administrator, open a published page and choose Inspect page images in the WordPress toolbar. Alternatively, open ImageFlow → Page Inspector → Inspect homepage.
  2. Set the browser to the width you want to check. Scroll to lazy-loaded content and open any popup or carousel slide of interest. Choose Pick image and click an image or background. Escape cancels selection. Scan viewport inspects up to 120 rendered image/background elements at the current page width, including elements below the fold.
  3. Expand a result to see the Elementor template/widget identifiers when exposed, viewport width, displayed dimensions, original candidate, observed URL and delivery finding. An ordinary image uses the browser’s currentSrc. Background results use computed CSS and available resource entries; ambiguous selections are labelled unconfirmed.

Explain & Fix

If a registered size lacks the preferred copy, select Generate missing … for that size. The repair uses current encoder, quality, exclusion and safety settings. For example, it can generate the missing 768px version while retaining other sizes. The server verifies whether the copy exists. Verify again on fresh load reloads the inspector and rescans browser selection. A larger derivative, unreadable source, unsupported codec or policy exclusion can prevent generation.

Double Download Check

“Original + alternative requests” lists matched URL pairs recorded by this browser during this navigation. Two resource entries can include cache hits, and another widget may use the same image. Treat the pair as evidence to investigate in the Network panel. A missing entry does not prove the file was never fetched.

4. Compare a template before and after a change

  1. On staging, open the page in Inspector mode at a reproducible viewport width. Reveal the widgets you want to include and click Save baseline.
  2. After editing the template, reload the same page in the same browser profile, with the same account, viewport width, device pixel ratio and interaction state.
  3. Click Compare baseline. The report shows added, removed or changed observations, including delivery state, URL, dimensions and request-pair counts. Save a separate baseline at mobile width.

Comparison uses widget/template identifiers and occurrence order. Reordered Loop Grid items can appear as changes. Baselines are stored locally in the browser, one per account/page/viewport combination. Saving again replaces that baseline.

5. Review usage before removal

Full scans save identified attachment IDs, page location, widget context, width and UTC scan time on this WordPress site. The latest 24 page/width scans are retained. A new scan replaces the previous observation for the same location. Picking a single image is a preview.

In Media Library Tools, check rows and choose Remove selected derivatives. The review shows matches from recent scans. Cancel or confirm removal. The attachment edit screen also offers a review before removal. An empty review means usage was not observed in the saved scans. Unscanned pages, hidden elements, other widths and cached pages can still reference those files. Use Logs & Tools → Restore original delivery first if you need to stop substitutions site-wide.

6. Tools, compatibility and troubleshooting

  • Elementor Integration shows server capabilities and offers manual CSS cache regeneration. Inspect the published page after regenerating or purging an external cache.
  • Logs & Tools exports settings as JSON, shows the last result per attachment, clears messages and restores original delivery. The CLI command wp imageflow convert 42 73 converts the specified attachment IDs.
  • Converted but original displayed? Check delivery settings, preferred format, complete responsive candidates, missing or stale copies and other optimizers. Run the Inspector at the affected width. Cross-origin assets, existing picture elements, signed URLs and complex CSS may continue to use the original.
  • Original and optimized both requested? Browser-side substitution can occur after the original request. Check request timing and initiators before attributing a transfer to ImageFlow.
  • No match for an external image? Repair requires a locally registered WordPress attachment and exact registered size. The inspector will not download remote media for conversion.
  • Privacy and storage. Conversion stays on the server. Inspector diagnostics are administrator-only. Browser comparisons remain on that device. Deactivation restores original rendering; plugin settings and conversions are retained.
